What Shepherd is

Shepherd is a self-hosted fleet manager for Grafana Alloy. It holds your collectors’ configuration centrally and serves each one exactly the config it should be running, over Alloy’s own remotecfg protocol. Collectors poll it; it never connects to them.

How it fits together

architecture
Alloy (spoke)  ──remotecfg──▶  Shepherd  ──serves──▶  merged Alloy config
                                  │
                 ┌────────────────┼────────────────────┐
                 ▼                ▼                    ▼
           PostgreSQL         Merge engine         Git (GitOps)
        (sessions, store)  (matcher + declare)      (repo_links)
  • Collectors authenticate with an agent token over HTTP Basic auth and poll for their configuration on an interval you choose.
  • The merge engine takes every enabled pipeline whose matchers select a given collector and merges them into the single config that collector is served.
  • PostgreSQL holds everything: pipelines, orgs, sessions, credentials. Shepherd itself is stateless, so you can run more than one replica.
  • Git is optional. A repo can be the source of pipelines instead of the UI — see GitOps.

What a collector actually gets

One merged config, assembled from the pipelines that match it. A collector that matches nothing is served an empty config rather than an error, so an unclaimed or unmatched collector keeps running whatever it already had locally — nothing is disrupted until somebody claims its cluster and enables pipelines that select it.

Every pipeline passes a three-stage validation gate before it can be served, so a config that would not start is refused at authoring time rather than discovered by a collector at 3am.

The beacon

Every claimed collector is also served a small baseline pipeline that reports which components it is running and whether they are healthy. It reports component names and health only — never config text, never raw samples. It is on by default; set server.beacon_disabled: true to turn it off.

What it is not

  • Not a telemetry backend. Shepherd never receives your metrics, logs or traces. It configures the collectors that ship them, and the data goes wherever your destinations point.
  • Not a replacement for Alloy. What Shepherd serves is ordinary Alloy config. Anything Alloy can run, it can serve; anything Alloy cannot, it refuses at the gate.
  • Not an agent installer. You deploy Alloy however you already do; Shepherd takes over from the point it starts polling.

Organisations

Everything is scoped to an organisation: collectors are claimed into one, pipelines belong to one, and roles are granted per organisation. An application administrator creates orgs and sets each one’s tenant identity; everyone else works inside one. See Roles and access.
