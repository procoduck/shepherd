Quickstart

Shepherd runs in your cluster and manages the Grafana Alloy collectors already there. This page installs it with Helm, points a collector at it, and serves that collector a pipeline — the whole loop, on a real cluster.

You need a Kubernetes cluster and helm, plus a PostgreSQL database Shepherd can reach. The chart does not ship a database: Shepherd keeps every pipeline, org and session there, so it should be one you are willing to back up. Any managed Postgres or an in-cluster operator is fine.

1. Create the secret

Two values are required and the server refuses to start without them. Generate the encryption key once and keep it — it encrypts git credentials and the OIDC client secret at rest, and a replacement key cannot decrypt what the old one wrote.

shell
kubectl create namespace shepherd

kubectl -n shepherd create secret generic shepherd-secrets \
  --from-literal=SHEPHERD_DATABASE_URL='postgres://user:pass@host:5432/shepherd' \
  --from-literal=SHEPHERD_SECURITY_ENCRYPTION_KEY="$(openssl rand -base64 32)" \
  --from-literal=SHEPHERD_BOOTSTRAP_ADMIN_PASSWORD='choose-a-password'

2. Install the chart

The chart is published as an OCI artifact, so there is nothing to clone and no repository to add.

shell
helm install shepherd oci://ghcr.io/procoduck/charts/shepherd --version 0.7.1 \
  --namespace shepherd \
  --set existingSecret=shepherd-secrets

kubectl -n shepherd rollout status deploy/shepherd

Database migrations run as a Helm pre-install/pre-upgrade hook, so helm install waits for the schema to be current before it creates the Deployment at all. The install above deliberately exposes nothing: route and ingress are both off by default, because an HTTPRoute needs Gateway API CRDs that a vanilla cluster does not have. Reach it with a port-forward first and decide how to expose it afterwards — see Exposing Shepherd.

shell
kubectl -n shepherd port-forward svc/shepherd 8080:8080

3. Sign in

Open http://localhost:8080 and sign in as admin with the bootstrap password from step 1. That account is created on first boot, only while the users table is empty. If you left the password out, it is admin/admin and can do nothing at all until you change it.

4. Mint a token and claim the cluster

Collectors authenticate with an agent token. Create one at Admin → Agent Tokens; the secret is shown exactly once. Then, once a collector has polled, Admin → Clusters shows the cluster it reported — claim it into an organisation, which is what makes its collectors manageable.

An unclaimed collector is served an empty config, not an error, so it keeps running whatever it already had. Nothing you do here disrupts a running fleet until you deliberately enable a pipeline that matches it.

5. Point Alloy at it

Add a remotecfg block to the Alloy instances you want managed. In-cluster, the URL is the chart’s Service:

config.alloy
remotecfg {
  url = "http://shepherd.shepherd.svc.cluster.local:8080"
  basic_auth {
    username = "<token-uuid>"
    password = "<token-secret>"
  }
  attributes = {
    cluster = "prod-eu-1",
    role    = "metrics",
  }
  poll_frequency = "60s"
}

The attributes are what pipelines select on, so they are worth choosing deliberately — see Matchers and validation. Within one poll interval the collector appears under Collectors.

6. Serve it a pipeline

Go to Pipelines and create one — from a wizard, in the visual builder, or by pasting Alloy. Give it matchers that select the collector you just connected, enable it, and watch the served config on that collector’s page change on its next poll.

That loop — author, match, serve — is all of Shepherd.
