GitOps

Instead of authoring in the UI, point Shepherd at a git repository and it will poll for *.alloy files and sync them onto a target collector as pipelines. Any git server works — the credential kinds are personal access token, basic auth, SSH deploy key, an Entra service principal for Azure DevOps, GitHub App installation tokens, and none for a public repository. Set it up under Git sync in the sidebar: add a credential, then a repository link naming the branch, the path and the collector its files are served to.

This page is about Shepherd’s own git sync, not about deploying Shepherd with Argo CD or Flux. If you are looking for the latter, three values matter and each has a default that is unsafe under a tool that renders the chart offline: see cnpg.render, externalSecrets.render, and the sandbox token — the chart generates it at install and looks it up on upgrade, which an offline render cannot do, so every sync would mint a new token and roll both Deployments. Set simulator.token.value or simulator.token.existingSecret (or simulator.enabled=false).

Synced pipelines show git in the Source column and are owned by the repository: they are read-only in Shepherd — the editor will not save them and they cannot be deleted. You can enable or disable one — that sticks — or restore an earlier revision, but the next commit to the repository puts the repository’s text back. A new file becomes an enabled pipeline on its first successful sync. Synced files pass the same three-stage validation gate as everything else, one file at a time: a file that fails is skipped (its previous version keeps being served), the others in the same commit still sync, and the error is shown under the link’s status on the Git sync page. Any synced pipeline can be read as a graph.

Removed files. A file removed from the repository has its pipeline deleted on the next successful sync; a renamed file is a removal of the old name and a new pipeline under the new one, in the same sync. Each delete is recorded in the audit log as a pipeline.delete by gitsync with the file and commit, and the collector’s served config is recomputed right away. A sync that could not fetch the repository, or in which any file failed validation, deletes nothing. Two guards hold a commit’s deletes back — its new and changed files still sync — and set the link’s status to warning, with the reason under it: a commit with no .alloy files at all under the link’s path while the link still has pipelines (usually a wrong path or branch), and a commit that would delete more than half of the link’s pipelines and more than three (a moved directory, or files removed before upgrading to the release that added this). While a link shows the warning, every poll fetches the repository again. To remove that many pipelines deliberately, delete and re-create the repository link, or remove fewer files per commit and let each sync complete in between.

Two pipelines in an organisation cannot have names that differ only in case or punctuation (a-b and a_b read as the same name). A file whose pipeline name clashes that way with another pipeline in the organisation, or with another file in the same commit, fails on its own with an error naming the other; the rest of the commit still syncs.

Git sync is managed by organisation admins.
