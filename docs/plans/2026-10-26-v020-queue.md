## 2. 0.19.1

### #389 Beacon ingest hardening

- A beacon write whose collector-id label is missing or unparseable is dropped and counted in a
  metric, instead of being stored under the writer's token.
- OIDC-bound agent identities get the same collector-in-org check (`beacon_denied`) bound tokens
  get since #386.
- Re-binding a token keeps its original cluster-claim right (`may_claim`): a rebind never grants a
  new right; an admin who wants a claiming token mints one. No API change.
- A beacon spec for the unclaimed-cluster drop.

### #400 In-browser preview caps

`web/src/visual/renderTS.ts` gets bounds like `internal/visual/render.go`'s (#393), looser on size:

| Bound | Server (`render.go`) | Browser |
|---|---|---|
| Total output | 1 MiB (`MaxRenderBytes`) | 4 MiB |
| Diagnostics | 200 / 64 KiB | 800 |
| Label, component name | 256 B | 256 B |

Name caps match because the server refuses longer names; previewing them would mislead. A hit
shows "too large to render" instead of a partial render.

## 3. 0.20

### #378 Module-based pipelines (role-enforcement half)

`signals.Derive` walks `declare` bodies, but an instance of a declared module
(`annotation_autodiscovery "feature"`) is not in the schema and counts as Unknown
(`internal/signals/derive.go:220`), which `RoleCheck` treats as every signal
(`internal/merge/enforce.go:155`), so restricted roles drop the pipeline.

- An instance of a module declared in the same pipeline is known and carries its declare body's
  signals.
- `import.string` content is parsed and its declares count the same way. Instances of modules from
  `import.file` / `import.git` / `import.http` stay Unknown.
- The beacon baseline stays outside a `declare`: no served-bytes change, no `serve.Format` bump.
  Nested beacon paths already roll up to their `pipe_*` segment (`internal/beacon/project.go:79`).

The grafana/k8s-monitoring chart (4.5.3 and 4.5.5, `helm template`) renders no import blocks: each
feature module is a `declare` in the same config text as its `<name> "feature"` instance. This item
is what makes chart pipelines work under restricted roles and in strict orgs.

### #362 Service-account viewer tier

- A viewer service account gets exactly what a viewer user gets (the existing viewer tier in
  `rpc_interceptor.go`; enforcement is already generic over `auth.ParseRole`).
- Migration: the role CHECK (`0018_service_account_role.up.sql:28`) admits `viewer`;
  `capability` becomes nullable — NULL for viewers, required for editor and admin.
- `serviceAccountTier` (`internal/mgmtapi/rpc_service_account.go:52`) stops refusing viewer; the
  UI (`web/src/pages/ServiceAccountsPage.tsx:29`) offers it and hides capability for it.
- Proto: comment edits only (approved); no wire change.

### #390 Pinned `import.git` for strict orgs

- Only `import.git` whose `revision` is a full 40-hex commit SHA. Alloy follows a moving tag
  (tags are fetched with force), so only a full SHA is immutable. `import.http` / `import.file`
  stay refused: Alloy has no integrity attribute for them, so a save-time hash check wouldn't bind
  what collectors fetch.
- An app admin allowlists repository URLs per org; pipelines use any full SHA from them. The tenant
  lint of the fetched content is the check; the allowlist bounds where Shepherd fetches from.
- Fetched at save time in the validation path, with git sync's size and time limits, and cached by
  (repository, SHA, path). A vanished source doesn't block later saves; a warning says collectors
  may fail to fetch it on restart.
- Nested imports in a fetched module follow the same rule, to depth 4.
- Private repositories reuse the credentials stored for git sync. `internal/gitrepo` needs a
  commit option (today it clones a branch tip, depth 1).
- New admin RPCs to list/add/remove an org's allowed repositories (proto change approved).

### #375 Version-aware validation

- Stage 3 checks each collector's merged config against the schema of every distinct Alloy version
  among its active instances (seen within the inactive threshold). Schemas for 1.18.1, 1.19.2 and
  1.20.1 already ship (`internal/schema/artifacts/`); today only the pin is loaded. A component or
  attribute missing from any of them refuses the save, naming the collector, version and item.
- A version no shipped schema covers, or none reported, falls back to the pinned schema with a
  warning.
- Experimental components get a warning naming the `--stability.level` flag collectors need.
- Serve time: a mismatch that appears after the save (an older pod joins) is flagged on the
  collector — a new collector field (proto change approved), audited once per change — and serving
  continues.
- Schema-only: `alloy validate` stays the single pinned binary.
- Spec §8 ("pinned Alloy version") is amended.
