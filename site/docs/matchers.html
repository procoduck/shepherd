Matchers and validation

A pipeline is a fragment of Alloy config plus the matchers that decide which collectors receive it. Those two questions — who gets this and is it safe to serve — are answered here, and they apply identically to every pipeline no matter which editor produced it.

Matchers decide who gets it

Matchers use Alertmanager syntax against the attributes a collector reports — cluster="prod-eu-1", role="metrics", role=~"metrics|logs". A pipeline with no matchers reaches nothing. The editor previews how many collectors currently match before you save, so "this matches nothing" is visible rather than discovered later.

The Source column is worth reading: ui, wizard, visual and git pipelines all merge identically, but a git one is owned by its repository and will be overwritten on the next sync.

The validation gate

Nothing reaches a collector without passing three stages:

  1. Syntax — the Alloy parser, with errors mapped back to line and column.
  2. Semantics — the real alloy validate binary, against the pinned Alloy version.
  3. Merge dry-run — the whole merged config for every affected collector. This is the stage that earns its keep: a pipeline can be perfectly valid on its own and still collide with one that is already running, and this catches that before any agent sees it.

A collector’s own page shows the exact merged config it is being served right now, which is the fastest way to confirm a matcher selected what you meant it to.
