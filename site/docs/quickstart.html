Quickstart

The fastest path to a Shepherd you can click through: the whole stack in Docker, seeded, with live Alloy collectors already polling it. Roughly five minutes, most of which is image pulls.

You need Docker, make, and a checkout of the repository. Nothing else — the dev stack brings its own PostgreSQL, mock identity provider, git server and collectors. For a production install see Kubernetes (Helm).

1. Start the stack

shell
git clone https://github.com/procoduck/shepherd.git
cd shepherd
make dev

That builds the images and brings up PostgreSQL, a seeded database, Shepherd, and a couple of real Alloy collectors pointed at it. When it finishes it prints the URL and the sign-in.

2. Sign in

Open http://localhost:8080 and sign in as admin / admin. This is a local development credential seeded by make dev; a real install sets its own on first boot — see Configuration.

3. Look at the fleet

Collectors lists the agents already talking to Shepherd, the cluster and role attributes each one reports, and when it last polled. Open one and you can see the exact merged config it is being served right now.

4. Change what they run

Go to Pipelines and create one — from a wizard, in the visual builder, or by pasting Alloy directly. Give it matchers that select a collector you just looked at, enable it, and watch the served config on that collector’s page change on its next poll.

That loop — author, match, serve — is all of Shepherd. Authoring pipelines covers the three editors and Matchers and validation covers how a pipeline finds its collectors and what Shepherd refuses to serve.

5. Tear it down

shell
make dev-reset   # stop everything and drop the volumes
