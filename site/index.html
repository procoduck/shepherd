Run a fleet of Grafana Alloy collectors from one place.

Shepherd is a self-hosted fleet manager for Grafana Alloy. Build pipelines visually or in Git, merge and validate them against a real Alloy binary, and serve them to every collector over Alloy's native remotecfg protocol — before anything reaches production.

// what it does

Everything a fleet manager needs, nothing it doesn't.

Shepherd is a Go backend and React SPA shipped as one binary. It speaks Alloy's agent protocol directly, so collectors need no extra sidecar to be managed centrally.

Fleet management over remotecfg

Alloy agents poll Shepherd with their native remotecfg block. Shepherd resolves each collector by (cluster, role), and unchanged config is skipped over content-hash / not-modified responses — no polling overhead for a quiet fleet.

collector.v1 · Connect RPC

Visual pipeline builder

A schema-driven canvas covering all 184 registered Alloy components. Drag components onto the canvas, wire them by typed ports, and undo/redo freely — the graph compiles to deterministic Alloy config through the same gate as everything else.

drag-to-wire · undo/redo

Merge engine & validation gate

Pipelines target collectors with Alertmanager-style matchers, and every config passes a three-stage gate — syntax, alloy validate against a pinned real Alloy binary, and a full merge dry-run — before it can ever be stored as servable.

never serve unvalidated config

GitOps from any git server

Point a repo link at a directory of .alloy files on any git host. Authenticate with a personal access token, an SSH deploy key, or a GitHub App installation — synced files pass the same validation gate before they're servable.

PAT · SSH · GitHub App

Sandbox simulation

Run a candidate pipeline against synthetic sources in a network-contained sandbox and inspect the captured series before it ever reaches a collector. Enabled by default as of v0.0.1 — a default-deny NetworkPolicy contains it, proven with in-cluster probes; turn it off per-deployment with simulator.enabled=false.

enabled by default · v0.0.1

RBAC, orgs, and an audit log

Multi-tenant by design: application admins manage orgs and set each one’s tenant identity, org admins manage their own collectors and pipelines, teams get scoped write, and readers get view-only access. Every mutating action is written to the audit log.

org-scoped roles

Tenant-aware gateway tier

OTLP and browser telemetry arrive on one endpoint per tenant. The gateway rewrites the prefix and sets the tenant header, so a client never chooses its own tenant — and tenant identity itself belongs to the org, assigned by an application administrator rather than supplied per request.

Gateway API, Standard channel

A beacon, not a survey

Every collector is served a small baseline pipeline that reports which components it is actually running, and whether they are healthy. Component names only — never config text, never raw samples. The collector you know nothing about is the one that would never have opted in.

inventory + health

An agent interface that cannot apply

An MCP server exposes the fleet to AI agents in read-plus-propose mode. The limit is enforced by the credential, not by which tools were registered: a propose-scoped service account is refused at every mutating endpoint, so a tool that does not exist yet would be refused too. A machine action records both the agent and the human it acts for.

read + propose, no apply

// how it fits together

One merge engine, three ways in.

Pipelines built by hand, drawn on the visual canvas, or synced from Git all become the same kind of row — matched to collectors, validated, and merged into one served config per collector.

// quick start

Deploy with Helm, point Alloy at it.

Images are published to GitHub Container Registry for linux/amd64 and linux/arm64. The chart lives at deploy/helm/shepherd in the repo.

1

Install the chart

Requires a Kubernetes secret with the database URL, encryption key, and OIDC secrets — see deploy/helm/shepherd/values.yaml for the full option list. Sandbox simulation ships enabled by default as of v0.0.1; add --set simulator.enabled=false to turn it off.

shell
helm install shepherd deploy/helm/shepherd \
  --set image.registry=ghcr.io/procoduck \
  --set image.tag=0.0.1 \
  --set existingSecret=shepherd-secrets \
  --set "route.enabled=true" \
  --set "route.hostnames[0]=shepherd.internal"
2

Point an Alloy collector at it

Add a remotecfg block to each collector's config.alloy, using a token minted with shepherd token create.

config.alloy
remotecfg {
  url = "https://shepherd.internal"
  basic_auth {
    username = "<token-uuid>"
    password = "<token-secret>"
  }
  attributes = {
    cluster = "<cluster-name>",
    role    = "metrics",
  }
  poll_frequency = "60s"
}
3

Or run it locally first

A single binary against Postgres — no Kubernetes required to try it out.

shell
docker run -d --name shepherd-pg \
  -e POSTGRES_DB=shepherd -e POSTGRES_USER=shepherd -e POSTGRES_PASSWORD=shepherd \
  -p 5432:5432 postgres:16-alpine

make build
SHEPHERD_DATABASE_URL=postgres://shepherd:shepherd@localhost:5432/shepherd \
SHEPHERD_SECURITY_ENCRYPTION_KEY=$(openssl rand -base64 32) \
  ./bin/shepherd migrate up && ./bin/shepherd serve

See the full getting-started guide for token creation, the dev stack, and the sandbox off-switch.
